# 架构说明

> 本文档说明「奇瑞互联」项目的技术架构。项目基于开源项目 DiPlay-CN（GPL-3.0）二次开发，针对奇瑞车机定制。

## 一、项目定位

「奇瑞互联」是一款运行在安卓车机上的 CarPlay 接收器：把它安装到车机后，通过 USB 有线或 Wi-Fi 无线连接 iPhone，即可在车机屏幕上使用苹果 CarPlay，无需外接转接盒、无需越狱。

## 二、模块划分

项目采用 Gradle 多模块架构，共 6 个模块，按职责分层、依赖单向：

```
mobile / automotive / samples/*   （应用层，用户安装）
        │
        ▼
     common                       （界面层）
        │
        ▼
     shared                       （协议核心层）
```

### shared —— 协议核心库（无界面）

车机与 iPhone 通信的全部底层协议都在这里，不依赖任何界面代码：

| 包 | 职责 |
| --- | --- |
| `iap2/` | iAP2 协议（Apple Accessory Protocol 2）：链路握手、会话管理、消息编解码、catalog、trace |
| `airplay/` | AirPlay 会话：配对（PairSetup）、验证（PairVerify）、视频流 |
| `mfi/` | MFi 配件认证客户端 |
| `transport/` | 传输层：USB、Wi-Fi Direct |
| `media/` | H.264 视频解码 + Opus 音频（基于 Concentus 编解码器） |
| `telecom/` | 通话、Siri 的音频通路 |
| `orchestration/` | 会话编排：连接 / 断开 / 切换的流程控制 |
| `hud/` | 比亚迪仪表 / HUD 相关能力 |
| `adb/`、`location/`、`compat/`、`network/`、`glance/` | 辅助能力 |

### common —— Android 界面层

依赖 `shared`，负责一切界面、设置与交互：

- `DiPlayActivity`：主设置界面（含完整的设置分类架构）
- `CarPlayHostActivity`：CarPlay 画面的渲染容器
- `settings/`：设置控件与各分类（连接 / 显示 / 音频 / 导航 / 车辆等）
- `AirPlayPersistence`：基于 SharedPreferences 的设置持久化
- 视频播放使用 media3 / ExoPlayer，二维码使用 zxing

### mobile —— 主应用

用户实际安装的应用（applicationId `com.shihab.diplay.cn`，minSdk 25，targetSdk 37）。包含签名配置、凭证校验、独立打包任务。

### automotive —— Android Automotive 应用

基于 androidx.car.app 的独立车机应用（minSdk 28）。

### samples/maphost、samples/home —— 示例应用

地图显示示例、主页启动器示例。

## 三、CarPlay 数据流

```
iPhone
  │  有线 USB / 无线 Wi-Fi Direct
  ▼
iAP2 链接握手 + MFi 认证       （shared/iap2、shared/mfi）
  ▼
AirPlay 会话（PairSetup / PairVerify）（shared/airplay）
  ▼
H.264 视频解码 + Opus 音频      （shared/media）
  ▼
渲染到车机屏幕                 （common，ExoPlayer）
```

反向链路：车机屏幕触摸 / 方向盘按键 → AirPlay 输入事件 → 回传 iPhone。

## 四、用到的 Android 组件

| 组件 | 项目中的实例 |
| --- | --- |
| Activity | `DiPlayActivity`（设置）、`CarPlayHostActivity`（CarPlay 渲染） |
| Service | `DiPlaySessionService`（前台服务）、`MyCarAppService`（androidx.car.app） |
| BroadcastReceiver | `BootReceiver`（开机自启）、`PhoneBluetoothReceiver`（蓝牙连接监听） |
| ContentProvider | `DiagnosticReportProvider`、`UpdateApkProvider`、`CrashRecordInstaller` |

## 五、构建系统

- 构建工具：Gradle 9.5 + Android Gradle Plugin 9.3 + Kotlin 2.2
- 依赖管理：版本目录（Version Catalog）统一管理所有依赖版本
- 原生代码：NDK 28，编译 C 代码（I2C、车载热点、Speex 回声消除）
- 编译目标：compileSdk 37，主应用 minSdk 25

## 六、测试体系

- 单元测试：JUnit + Robolectric（含界面 / 设置相关测试）+ Mockito
- 关键测试：
  - `SettingsTranslationsTest`：校验 `settings_` 前缀字符串在所有语言目录完整翻译
  - `SettingsLayoutPolicyTest`：校验设置分类架构（每个设置项只属于一个分类）
  - `AdaptiveSettingsUiTest`：校验设置页面的布局与分类导航

## 七、奇瑞定制改动

1. **车辆品牌设置**：在「设置 → 车辆」新增「车辆品牌」选项（比亚迪 DiLink / 奇瑞）。选择「奇瑞」时，自动隐藏比亚迪专属的仪表盘与导航功能（奇瑞车机不具备比亚迪的 DiLink 仪表 / HUD 协议）。
2. **品牌改造**：应用名、界面标题、图标改为「奇瑞互联」。

涉及的改动文件：

- `common/src/main/java/com/shilapi/xcertplay/DiPlayActivity.kt`（设置架构与界面）
- `common/src/main/java/com/shilapi/xcertplay/AirPlayPersistence.kt`（持久化）
- `common/src/main/res/values*/strings.xml`（8 种语言翻译）
- `common/src/main/res/drawable/ic_carplay.png`（图标）
